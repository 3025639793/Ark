# Ark · 私人图片方舟

为喜欢的二次元角色图片留一个位置。一个可以自己部署的私人图片收藏库：图片原文件与分类保存在服务器，电脑和手机访问同一个服务器地址即可查看同一份收藏。

## 已实现

- 密码解锁、7 天登录状态、服务端保护原图与分类接口。
- 多选上传、拖拽上传，支持 JPG、PNG、GIF、WebP，单张最多 25 MB。
- 角色、作品、标签、画师、来源链接、特别喜欢。
- 瀑布流浏览、角色收藏墙、搜索、作品与标签筛选、排序。
- 批量设置角色和作品、批量追加标签。
- 大图浏览、方向键切换、原图下载、删除确认。
- 导出 JSON 分类记录（不包含原图，不是完整备份）。
- 电脑和手机响应式布局。

这是单用户版本，所有登录设备共用一个图片库。没有自动识别角色、多人账号或图片压缩。图片不会被提交到 GitHub。

## 本地启动

需要 Node.js 24 或更新版本，无第三方运行依赖。

```sh
cp .env.example .env
```

在 `.env` 中填写 `ARK_PASSWORD`（至少 12 个字符），然后：

```sh
node --env-file=.env server.mjs
```

电脑打开 `http://localhost:3000`。手机和电脑处于同一局域网时，手机访问 `http://电脑的局域网IP:3000`，并允许防火墙放行此端口。局域网地址不提供外网访问；电脑关闭后网页也会停止运行。

## Docker 部署

```sh
cp .env.example .env
# 编辑 .env，填写访问密码
docker compose up -d --build
```

在服务器部署同样的服务后，所有设备访问该服务器地址即可。正式外网使用应在前面配置 HTTPS 反向代理，并将 `.env` 中的 `ARK_SECURE_COOKIE` 设为 `1`。不要为 HTTP 地址启用 Secure Cookie，否则浏览器无法保持登录。

环境变量：

| 变量 | 用途 | 默认值 |
| --- | --- | --- |
| `ARK_PASSWORD` | 访问密码，必填，至少 12 字符 | 无 |
| `PORT` | HTTP 端口 | `3000` |
| `HOST` | 监听地址 | `0.0.0.0` |
| `ARK_DATA_DIR` | 数据持久化目录 | `./data` |
| `ARK_SECURE_COOKIE` | HTTPS 部署时设置为 `1` | `0` |

不要把密码、`.env` 或数据目录提交到代码仓库。修改密码需要重启服务；已有登录会话仍会在 7 天内有效。需要立即撤销所有登录时，停止服务后清空 `sessions` 表。

## 数据与备份

原图位于 `data/images/`，分类及会话位于 `data/ark.sqlite`。Docker 使用 `ark-data` 持久卷保存此目录，重新构建或重启容器不会清空数据。不要执行 `docker compose down -v`，这会删除数据卷。

完整备份：停止服务，复制整个数据目录或 Docker 数据卷，再启动。恢复时将完整目录放回数据位置。导出的分类 JSON 仅供查看和迁移，目前没有 JSON 导入功能。

## 验证

```sh
npm run check
npm test
```

集成测试会启动临时服务，验证登录、未授权访问、原图读写、分类修改、非法来源链接、跨站写入、文件格式与大小限制、重启后数据与会话持久化、删除和退出登录。测试数据会自动清理。

## 技术

Node.js 原生 HTTP、内置 SQLite、原生 HTML / CSS / JavaScript。无需付费 AI API。托管需要支持持久磁盘或 Docker 数据卷；临时文件系统的静态托管平台不能直接运行这个版本。

目前尚未部署到外网。本仓库提供可运行源码与部署配置。
